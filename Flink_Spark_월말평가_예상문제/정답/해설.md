# 정답과 해설

완성 파일은 정답/problem/에 있습니다. 그 폴더에서 응시용과 같은 실행 명령을 사용합니다.

| 문항 | 정답과 채점 기준 |
|---|---|
| 01 | get_execution_environment, set_parallelism, from_collection, INT, filter, map. 음수만 제외하고 0을 유지합니다. 변환 정의 후 execute_and_collect가 실행합니다. |
| 02 | master, appName, getOrCreate, parallelize, count. local[2]는 로컬 실행 스레드 수이며 RDD 파티션 수는 parallelize의 두 번째 인자로 별도 설정합니다. count는 Action입니다. |
| 03 | CHECKPOINT 1000 EXACTLY_ONCE 및 순서대로 정리된 5개 행을 비교합니다. POSIX 시간대 변환이 필요 없는 정수 밀리초 입력입니다. A의 4,999ms와 5,000ms를 서로 다른 창으로 분류합니다. |
| 04 | 완성 명령은 problem4/commands.txt에 있습니다. 10을 포함하며 중복도 남습니다. 26 이상은 0건입니다. |
| 05 | flat_map에서 여러 토큰을 내보낸 다음 필터를 적용합니다. key_by의 첫 필드가 코드, sum(1)의 두 번째 필드가 건수입니다. 각 이벤트 처리 뒤 중간 누적값이 출력됩니다. |
| 06 | flatMap으로 펼치고 map으로 소문자화한 후 토큰의 집합 포함 여부를 검사합니다. 부분 문자열 검사로는 bay, gate까지 빠집니다. reduceByKey는 키별 합을 구하고 takeOrdered는 지정 순위의 결과를 가져오는 Action입니다. |
| 07 | DataFrame은 유효 측정을 먼저 거르고 LEFT JOIN합니다. SQL은 필터를 ON 절에 둡니다. WHERE에서 r.units를 걸러버리면 미매칭 관측소가 사라집니다. COUNT(r.units)는 NULL을 세지 않고 COALESCE가 합계 0을 보장합니다. |
| 08 | 모범 문장은 problem8.txt에 있습니다. (1) 2개 창과 끝 경계 (2) 3,000ms의 창 배정·합계·최종 워터마크 (3) 간격 의미·실제 완료와 엔드투엔드 보장 조건을 각각 확인합니다. |

Q03의 실제 복원 시험은 요구하지 않습니다. 검사는 체크포인트 설정 값과 유한 입력의 결과를 대조합니다. Q05의 정렬은 표시 편의용이므로 런타임의 전체 도착 순서로 해석하지 않습니다.
