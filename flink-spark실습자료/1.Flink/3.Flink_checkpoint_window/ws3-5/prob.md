| 학습 방향  
입력 순서가 이벤트 발생 순서와 다를 때는 지연 데이터를 처리하는 기준이 필요하다. 
본 실습에서는 일부 센서 이벤트를 과거 시각으로 생성하고, 허용 지연에 따른 창 갱신과 별도 출력을 확인한다.
지연 이벤트 처리: 1초 워터마크와 3초 허용 지연을 설정하고, WINDOW와 TOO LATE 출력을 통해 처리 결과를 구분한다.  

요구사항
1.    실행 환경 생성
   StreamExecutionEnvironment.get_execution_environment()를 사용하여 실행 환경을 생성하세요. 제공된 병렬성 설정을 유지하고 입력부터 결과 출력까지의 처리 흐름을 구성하세요.

2.    센서 데이터 및 이벤트 시각 준비
   제공된 datagen 설정으로 n=0~25를 초당 한 건씩 생성하세요. 측정값은 20+n이며 기본 이벤트 시각은 (n+1)*1000ms입니다.
   n=7은 3000ms, n=18은 4000ms로 시각을 되돌리는 코드를 유지하세요. 입력 도착 순서와 이벤트 시각의 차이를 확인하고 두 지연 입력의 처리 결과를 비교하세요.

3.    데이터 스트림 생성
   TimestampAssigner로 세 번째 필드의 시각을 추출하세요. for_bounded_out_of_orderness()의 빈칸에 Duration.of_seconds(1)을 완성하여 워터마크를 구성하세요.

4.    허용 지연 및 사이드 출력
   5초 이벤트 시간 창의 allowed_lateness()에 3000을 지정하세요. side_output_late_data()의 빈칸을 채워 too-late 태그를 연결하고 제공된 reduce 집계를 유지하세요.

5.    프로그램 실행
   execute_and_collect()로 결과를 출력하세요. WINDOW의 갱신과 TOO LATE 데이터를 구분하고, 처리 스케줄과 워터마크 진행에 따라 중간 출력 시점이 달라질 수 있음을 확인하세요.
